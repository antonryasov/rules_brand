# Как устроен репозиторий

## Три части

```
САЙТ (GitHub Pages)            WORKER (Cloudflare)              БАЗА (D1)
index.html + content/ +  ───►  /order, /catalog, /admin  ───►  orders, products,
data/ + assets/                Telegram-боты                    order_items, outbox
```

1. **Сайт** — статические файлы. Хостинг бесплатный, GitHub Pages.
2. **Worker** — небольшой сервер, который принимает заказы и отдаёт данные кабинету.
3. **D1** — база Cloudflare, в которой лежат заказы, товары и переписка.

Сайт при открытии спрашивает у Worker актуальный каталог. Если Worker не ответил —
показывает товары из файла `data/products.json`. Поэтому витрина не «падает»
никогда, даже если база временно недоступна.

## Как сайт собирает страницу

```
index.html                — оболочка: шапка, меню, корзина, футер
 ├─ assets/js/config.js   — технические константы
 ├─ assets/js/store.js    — загрузка data/*.json и /catalog, промокоды, расчёты
 ├─ assets/js/render.js   — HTML карточек товаров и страницы товара
 ├─ assets/js/motion.js   — анимации, мобильное меню, фильтры, квиз
 ├─ assets/js/cart.js     — корзина, оформление заказа, отправка на Worker
 ├─ assets/js/router.js   — переключение страниц по адресу #/...
 └─ assets/js/main.js     — запуск и сборка страницы из content/ + data/
```

Адреса страниц — с решёткой: `…/rules_brand/#/catalog`, `…/#/candle-kodeks`.
Это позволяет менять страницу без перезагрузки и без настройки сервера.

| Страница | Адрес |
|---|---|
| Главная | `#/index` |
| Каталог | `#/catalog` |
| Товар или набор | `#/<id>.html`, например `#/candle-kodeks` или `#/set-pravila` |
| Остальные | `#/about`, `#/delivery`, `#/returns`, `#/documents`, `#/contacts`, `#/quiz`, `#/promo-…` |

## Что откуда берётся

| На сайте | Источник |
|---|---|
| Тексты страниц | `content/*.html` |
| Каталог (цены, остатки, фото) | Worker `/catalog` → база `products`, резерв — `data/products.json` |
| Цвета, шрифты, контакты, реквизиты | `data/settings.json` |
| Промокоды | `data/promos.json` + проверка на Worker |
| Вопросы квиза | `data/quiz.json` |
| Названия вкладок | `data/pages.json` |
| Стили | `assets/css/*.css` |
| Фото | `assets/img/**` |

## Куда идут заказы

1. Покупатель нажимает «Оформить» → `cart.js` отправляет POST `/order`.
2. Worker проверяет цены и остатки по базе, списывает остаток, создаёт заказ.
3. В Telegram владельцу уходит сообщение с составом и суммой, в базу — запись в очередь.
4. Покупатель получает ссылку «Отслеживать заказ» — это бот для покупателей
   (`@rules_clients_bot`), у каждого заказа свой секретный код.
5. В кабинете заказ виден сразу; смена статуса отправляет покупателю сообщение.

Два бота специально разделены:

- **бот заказов** (`TELEGRAM_BOT_TOKEN`) — только для вас, входящие заказы и ответы покупателей;
- **бот покупателей** (`CUSTOMER_BOT_TOKEN`, `@rules_clients_bot`) — статусы, «Мои заказы», каталог.

## Безопасность

- Пароль кабинета живёт в секретах Cloudflare, в репозитории его нет.
- Вход ограничен: 8 попыток за 15 минут с одного IP, пароль короче 16 символов не принимается.
- Сессия — подписанный токен на 12 часов, хранится в localStorage браузера.
- Каталог отдаётся сайту только для домена из `ALLOWED_ORIGIN`.
- Ссылка на заказ содержит случайный код: угадать чужой заказ нельзя.
- Вебхук бота покупателей защищён секретным путём `WEBHOOK_SECRET`.
