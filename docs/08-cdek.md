# СДЭК: подключение по шагам (от нуля до работающего расчёта)

> **Статус: отложено.** Сейчас корзина не использует СДЭК: покупатель вводит адрес руками
> (см. [docs/07-obnovlenie.md](07-obnovlenie.md), раздел 8). Ключи и настройки ниже нужны
> только если вы решите включить автоматический расчёт позже — на приём заказов это не влияет.

Инструкция для случая, когда сайт и Worker уже обновлены, а СДЭК ещё не подключён.
Время: 10–20 минут (плюс ожидание договора и ключей от СДЭК).

---

## 0. Что даёт интеграция и чего она не делает

**Делает:**

- в корзине появляются варианты «СДЭК — пункт выдачи», «СДЭК — курьером до двери»;
- по городу покупателя показывает список **пунктов выдачи и постаматов** с адресами и часами работы;
- считает **стоимость и срок** доставки по тарифам СДЭК и показывает «К оплате с доставкой»;
- выбранный адрес ПВЗ и стоимость доставки сохраняются в заказе: вы видите их в Telegram
  и в карточке заказа в кабинете, покупатель — в боте;
- стоимость **пересчитывается на сервере** при приёме заказа, подменить её из браузера нельзя.

**Не делает (это отдельная доработка, если понадобится):**

- не создаёт накладные/заявки в СДЭК — отправление вы по-прежнему оформляете
  в личном кабинете СДЭК, а трек-номер вбиваете в карточку заказа;
- не рисует карту (пункты выводятся списком);
- не бронирует дату забора курьером.

Схема запросов:

```
браузер (корзина)  →  Worker (Cloudflare)  →  api.cdek.ru/v2
                       ключи лежат в секретах,
                       стоимость пересчитывается при заказе
```

## 1. Что нужно получить на стороне СДЭК

### 1.1. Договор

Боевые ключи API СДЭК выдаёт **по действующему договору** — как правило с ИП или ООО
(договор интернет-магазина «ИМ»). Без договора доступен только тестовый контур.

> ⚠️ В реквизитах сайта указано «самозанятый». У СДЭК API-доступ оформляется на
> ИП/юрлицо, поэтому:
> - если у вас есть ИП или вы готовы его оформить — идём по этой инструкции;
> - если нет — уточните у менеджера СДЭК, могут ли выдать ключи на вашу форму;
>   пока ключей нет, корзина работает в режиме «Обсудить с продавцом» (заказы принимаются).

### 1.2. Ключи API (Client ID и Client Secret)

1. Войдите в личный кабинет СДЭК: **https://lk.cdek.ru/**.
2. Откройте раздел **«Интеграция»** (в некоторых версиях кабинета — «Настройки» → «API-доступ»;
   прямой адрес: `https://lk.cdek.ru/integration`).
3. Нажмите **«Создать новый ключ»** (или «Создать ключ»).
4. Система покажет пару:
   - **Client ID** (он же Account) — например `abcdEFGH1234567`;
   - **Client Secret** (он же Secure password) — длинная строка.
5. **Скопируйте секрет сразу** — он показывается один раз. Потеряете — придётся создавать новый ключ.

Если раздела нет — напишите на **integration@cdek.ru** (или своему менеджеру) с просьбой
выдать доступ к API v2 по номеру договора.

### 1.3. Город отправки

Запомните город, откуда физически уезжают посылки (обычно Москва). Он пойдёт в переменную
`CDEK_FROM_CITY` и должен совпадать с городом склада в договоре.

### 1.4. Тарифы

По умолчанию в коде стоят:

| Что | Тариф | Название |
|---|---|---|
| пункт выдачи | `136` | Посылка склад-склад |
| курьер до двери | `137` | Посылка склад-дверь |

Если по вашему договору эти тарифы недоступны, используйте:

| Тариф | Название | Когда подходит |
|---|---|---|
| `234` | Экономичная посылка склад-склад | дешевле, дольше (из Москвы за Урал и в Крым) |
| `233` | Экономичная посылка склад-дверь | то же, курьером |
| `368` | Посылка склад-постамат | если работаете только через постаматы |

Код доступного тарифа подтвердит менеджер СДЭК. В коде уже есть **резервная цепочка**:
если основной тариф недоступен, Worker сам пробует `234`, затем `368` (для ПВЗ) и `233` (для курьера).

## 2. Куда что кладём: файлы и настройки

| Что | Куда | Обязательно? |
|---|---|---|
| `worker/worker.js` (собранный файл, ~165 КБ) | **Cloudflare** → Worker `rules-orders` → Edit code → вставить → **Deploy** | да, если у вас версия без СДЭК |
| Секреты `CDEK_CLIENT_ID`, `CDEK_CLIENT_SECRET` | **Cloudflare** → Worker → Settings → Variables and Secrets | да |
| Переменные `CDEK_TEST`, `CDEK_FROM_CITY`, `CDEK_TARIFF_PVZ`, `CDEK_TARIFF_COURIER`, `CDEK_WEIGHT`, `CDEK_LENGTH`, `CDEK_WIDTH`, `CDEK_HEIGHT` | там же | желательно |
| `index.html`, `assets/js/cart.js`, `assets/css/shop.css` | **GitHub** (репозиторий `rules_brand`) | только если корзина ещё без блока «Доставка» |
| `worker/src/worker.js`, `admin/*`, `docs/*` | **GitHub** | для истории, на работу не влияет |
| база D1, `schema.sql`, боты Telegram | — | ничего делать не нужно |

Правило простое: **всё, что запускается на сервере, — в Cloudflare; всё, что видит браузер, — в GitHub.**

## 3. Шаг 1. Проверить, что Worker уже умеет СДЭК

Откройте в браузере (или в терминале):

```
https://rules-orders.antnrsv.workers.dev/delivery/config
```

**Вариант А** — ответ такой:

```json
{"ok":true,"cdek":{"enabled":false},"methods":["discuss"]}
```

Значит код СДЭК в Worker уже есть, ключей нет. Переходите к шагу 3.
(Сайт в этом состоянии показывает только «Обсудить с продавцом» — это нормально.)

**Вариант Б** — `404` или страница с текстом `RULES`:

```
RULES
```

Значит в Cloudflare старая версия Worker. Возьмите из репозитория файл **`worker/worker.js`**
(это собранный файл, не `worker/src/worker.js`), вставьте целиком в
Cloudflare → Worker → **Edit code** → **Deploy** → проверьте адрес снова.

## 4. Шаг 2. Проверить корзину на сайте

Откройте сайт → Каталог → «В корзину» → «Оформить» → прокрутите до поля «Город доставки».
Под ним должен быть блок **«Доставка»** с тремя вариантами.

- **Блок есть, два верхних варианта серые** — всё правильно, ждут ключей СДЭК.
- **Блока нет совсем** — в репозитории старый `index.html`/`cart.js`. Тогда в GitHub
  обновите три файла: `index.html`, `assets/js/cart.js`, `assets/css/shop.css`
  (фрагменты — в `docs/07-obnovlenie.md`, раздел 7).

## 5. Шаг 3. Добавить ключи в Cloudflare

1. Откройте **dash.cloudflare.com** → слева **Workers & Pages** → ваш Worker **`rules-orders`**.
2. Вкладка **Settings** (Настройки).
3. Раздел **Variables and Secrets** (в старом интерфейсе — «Variables» → «Environment Variables»).
4. Нажмите **Add** / **Add variable** и добавьте по одной:

| Имя | Тип | Значение |
|---|---|---|
| `CDEK_CLIENT_ID` | **Secret** | Client ID из ЛК СДЭК |
| `CDEK_CLIENT_SECRET` | **Secret** | Client Secret из ЛК СДЭК |
| `CDEK_TEST` | Text | `0` — боевой контур (`1` — тестовый) |
| `CDEK_FROM_CITY` | Text | `Москва` (ваш город отправки) |
| `CDEK_TARIFF_PVZ` | Text | `136` (или `234` / `368` по договору) |
| `CDEK_TARIFF_COURIER` | Text | `137` (или `233`) |
| `CDEK_WEIGHT` | Text | `1500` — вес посылки в **граммах** |
| `CDEK_LENGTH` | Text | `30` — длина, см |
| `CDEK_WIDTH` | Text | `20` — ширина, см |
| `CDEK_HEIGHT` | Text | `15` — высота, см |

5. Нажмите **Save** и затем **Deploy** (кнопка «Save and deploy»), если Cloudflare её предлагает.
   **Без Deploy переменные не заработают** — это самая частая ошибка.

> Секреты (`Secret`) после сохранения прочитать нельзя — это нормально, они хранятся в зашифрованном виде.
> Значения не попадают в репозиторий и в браузер.
>
> Габариты влияют на стоимость: свеча 200 г в коробке — примерно `1500` г, `30×20×15` см.
> Если отправляете наборы, поставьте, например, `2500` г и `40×30×20` см.

Проверка, что переменные подхватились: откройте `/delivery/config` снова — должно быть

```json
{"ok":true,"cdek":{"enabled":true,"test":false,"fromCity":"Москва"},"methods":["cdek_pvz","cdek_courier","discuss"]}
```

### Проверка из кабинета (без curl)

Личный кабинет → **Настройки** → блок **«Доставка СДЭК»**:

- «Не подключено» — ключей нет (или не нажат Deploy);
- «Подключено» + строка с городом отправки, тарифами и весом;
- кнопка **«Проверить расчёт и пункты выдачи»** запрашивает у СДЭК стоимость
  и количество пунктов в городе отправки. Успех выглядит так:
  «Всё работает. Москва: доставка 390 ₽ · срок 1–2 дн. · тариф 136 · пунктов в городе: 412».
  При ошибке показывается её текст от СДЭК — сразу понятно, что чинить.

## 6. Шаг 4. Проверить связку с СДЭК (три запроса)

Подставьте свой домен Worker.

**1) Город и пункты выдачи**

```
https://rules-orders.antnrsv.workers.dev/delivery/points?city=Москва
```

Ожидаемо:

```json
{"ok":true,"city":{"code":44,"city":"Москва","region":"Москва"},
 "points":[{"code":"MSK123","name":"...","address":"Москва, ул. ...","workTime":"Пн-Пт 10:00-20:00","kind":"Пункт выдачи"}]}
```

**2) Стоимость доставки** (в терминале):

```bash
curl -X POST https://rules-orders.antnrsv.workers.dev/delivery/calc \
  -H 'content-type: application/json' \
  -d '{"city":"Москва","method":"cdek_pvz"}'
```

Ожидаемо: `{"ok":true,"cost":390,"periodMin":1,"periodMax":2,"tariff":136,"city":"Москва"}`.

**3) Для курьера** — то же с `"method":"cdek_courier"`.

Если все три отвечают `ok:true` — серверная часть готова, дело за сайтом.

## 7. Шаг 5. Проверить в браузере (как это увидит покупатель)

1. Откройте сайт, добавьте товар в корзину, нажмите «Оформить».
2. В поле **«Город доставки»** введите `Москва`.
3. Выберите **«СДЭК — пункт выдачи»**.
4. Нажмите **«Найти пункты выдачи в моём городе»** — появится список адресов
   с пометкой «Пункт выдачи» или «Постамат» и часами работы.
5. Выберите пункт — под списком появится «Доставка СДЭК: 390 ₽ · срок 1–2 дн.»,
   а в итогах — строка «Доставка» и «К оплате с доставкой».
6. Оформите заказ → в Telegram владельцу придёт строка
   «Доставка: СДЭК, пункт выдачи · Москва, ул. … — 390 ₽».
7. В кабинете откройте заказ: поле **«Пункт выдачи (адрес СДЭК)»** заполнено,
   «Стоимость доставки» — 390, в переписке и боте покупатель видит адрес.

Проверьте и второй сценарий: «СДЭК — курьером до двери» — стоимость считается без выбора пункта.

## 8. Что видит покупатель и что видите вы

| Где | Что появляется |
|---|---|
| Корзина, поле «Доставка» | 3 варианта; после выбора ПВЗ — список адресов |
| Итоги корзины | «Доставка 390 ₽», «К оплате с доставкой 2 080 ₽» |
| Экран «Заказ принят» | строка с адресом ПВЗ и стоимостью доставки |
| Telegram владельцу | `Доставка: СДЭК, пункт выдачи · <адрес> — 390 ₽` |
| Кабинет, карточка заказа | «Пункт выдачи (адрес СДЭК)», «Стоимость доставки», способ доставки |
| Бот покупателя, карточка заказа | способ, адрес, стоимость, итог с доставкой |
| Уведомление о смене статуса | `Доставка: СДЭК, пункт выдачи`, адрес, стоимость |

Итого по деньгам: **`total` в заказе — это товары; доставка хранится отдельно**,
поэтому в выгрузках есть и то, и другое (в CSV — колонки доставки, в JSON — все поля).

## 9. Если что-то не работает

| Сообщение / симптом | Причина | Что делать |
|---|---|---|
| В корзине оба варианта СДЭК серые, «Онлайн-расчёт СДЭК пока недоступен» | Worker не отдал `/delivery/config` с `enabled:true` | нет ключей, не нажат **Deploy**, или в Worker старый код (шаг 1) |
| `{"error":"Доставка СДЭК ещё не подключена."}` | в Worker нет `CDEK_CLIENT_ID`/`CDEK_CLIENT_SECRET` | добавить секреты и нажать Deploy |
| `СДЭК: не удалось авторизоваться. Проверьте CDEK_CLIENT_ID и CDEK_CLIENT_SECRET.` | неверные ключи или перепутан контур: тестовые ключи с `CDEK_TEST=0` (или наоборот) | перепроверить пару ключей и `CDEK_TEST` |
| `Город «…» не найден в базе СДЭК.` | опечатка или СДЭК не обслуживает город | проверить написание; для новых городов СДЭК — проверить на сайте cdek.ru |
| Список пунктов пустой («Найдено 0») | в городе только курьерская доставка | покупатель выбирает «курьером» или «обсудить с продавцом» |
| `СДЭК: тариф не найден` / стоимость 0 | тариф не входит в ваш договор | поменять `CDEK_TARIFF_PVZ` на `234` или `368`, `CDEK_TARIFF_COURIER` на `233` (спросить менеджера) |
| `Доставка СДЭК пока не настроена — выберите «обсудить с продавцом»` при оформлении | ключи в Worker есть, но запрос к СДЭК падает | открыть `/delivery/calc` и посмотреть текст ошибки |
| В консоли браузера ошибка CORS | `ALLOWED_ORIGIN` не совпадает с адресом сайта | Cloudflare → переменная `ALLOWED_ORIGIN` = `https://antonryasov.github.io` |
| Стоимость «скачет» между проверками | у СДЭК меняются тарифы/топливо | нормально; при заказе цена фиксируется в момент оформления |

Полный текст ошибки СДЭК всегда виден в ответах `/delivery/points` и `/delivery/calc`.

## 10. Тестовый контур (если хотите проверить до получения боевых ключей)

1. Поставьте `CDEK_TEST = 1` — Worker будет ходить на `api.edu.cdek.ru/v2`.
2. Тестовые ключи публикуются в официальной документации СДЭК:
   **https://apidoc.cdek.ru/** (раздел авторизации, OAuth 2.0).
3. Проверьте `/delivery/points` и `/delivery/calc`.
4. После проверки обязательно верните `CDEK_TEST = 0` и **боевые** ключи — иначе
   расчёт будет тестовым, а заказы реальными.

В тестовом контуре есть только справочники и калькулятор — накладные там не создаются,
и это нормально: наша интеграция накладные и не создаёт.

## 11. Что можно добавить позже

| Доработка | Что нужно |
|---|---|
| Бесплатная доставка от суммы (например, от 5 000 ₽) | одна проверка в `assets/js/cart.js` (обнулять `delivery.cost`) и в `resolveDelivery` на сервере |
| Карта пунктов вместо списка | подключить Яндекс.Карты и отрисовать `latitude`/`longitude` (они уже приходят из API) |
| Создание накладных СДЭК прямо из кабинета | метод `/v2/orders`, печать ШК `/v2/print/orders/{uuid}.pdf`, вебхуки статусов |
| Автоподстановка трек-номера | те же вебхуки СДЭК → запись в `orders.tracking` |
| Разный вес/габариты для наборов | считать вес по составу заказа вместо фиксированного `CDEK_WEIGHT` |
