# Как менять сайт через GitHub

Всё делается в браузере: открываете файл в репозитории → карандаш «Edit» →
правите → «Commit changes». Через 1–2 минуты GitHub Pages показывает новую версию.

> Если правок много, удобнее править в [github.dev](https://github.dev) —
> нажмите `.` на странице репозитория и получите редактор как в VS Code.

---

## 1. Тексты страниц

Файлы лежат в папке **`content/`**. Один файл = одна страница.

| Файл | Страница на сайте |
|---|---|
| `content/index.html` | Главная (`#/index`) |
| `content/catalog.html` | Каталог (`#/catalog`) |
| `content/about.html` | О бренде |
| `content/delivery.html` | Доставка и оплата |
| `content/returns.html` | Возврат и обмен |
| `content/documents.html` | Документы (оферта, политика) |
| `content/contacts.html` | Контакты |
| `content/promo-first-batch.html` | Первая партия |
| `content/promo-sampler.html` | Пробники |
| `content/promo-gift.html` | Подарки и наборы |
| `content/promo-partners.html` | Партнёрам |
| `content/quiz.html` | Квиз |

Как читать файл: текст внутри тегов — это и есть текст на сайте.

```html
<h1 class="h-xl">Каталог</h1>
<p class="lead">Шесть ароматов в свечах и четыре в диффузорах.</p>
```

Классы (`h-xl`, `lead`, `kicker`) — это оформление, их лучше не менять,
а слова внутри — меняйте свободно.

Полезные классы:

| Класс | Как выглядит |
|---|---|
| `h-xl` | огромный заголовок |
| `h-l` | крупный заголовок |
| `lead` | вводный абзац крупным шрифтом |
| `kicker` | маленькая надпись с чёрточкой сверху |
| `note` | серое примечание |
| `<em class="it">` | курсив |

**Подстановки.** В любом месте страницы можно написать:

| Код | Что подставится |
|---|---|
| `{{brand.name}}` | название бренда |
| `{{brand.legal}}` | реквизиты продавца |
| `{{contacts.email}}` | e-mail |
| `{{contacts.telegram}}` | Telegram |
| `{{contacts.vk}}` | VK |

Значения задаются в `data/settings.json` — поменяли один раз, обновилось на всех страницах.

## 2. Товары: цены, названия, описания

Два способа.

**Способ А (рекомендуется) — личный кабинет.** Раздел «Товары и склад».
Изменения сразу попадают на сайт.

**Способ Б — файл `data/products.json`.** Это резервная копия каталога и
одновременно исходник для первичной заливки в базу.

```json
{
  "id": "candle-kodeks",
  "page": "candle-kodeks.html",
  "name": "Кодекс",
  "price": 1690,
  "stock": 12,
  "tagline": "Кожа, табак, амбра",
  "lead": "Кожаная куртка, табак и тёплая амбра…",
  "notes": { "top": "чёрный перец, кожа", "heart": "табак, сандал", "base": "амбра, тонка" },
  "images": { "card": "assets/img/products/candle-kodeks.webp",
              "hero": "assets/img/products/candle-kodeks-hero.webp" }
}
```

| Поле | Смысл |
|---|---|
| `id` | внутренний код товара (латиницей). Не меняйте, если товар уже продаётся |
| `page` | адрес страницы товара: `candle-kodeks.html` → `#/candle-kodeks` (у наборов — `set-pravila.html` → `#/set-pravila`) |
| `price` / `oldPrice` | цена и «старая цена» (зачёркнутая) |
| `stock` | остаток. `0` — на сайте появится «Нет в наличии» |
| `active` | `false` — товар скрыт с сайта |
| `tagline` | короткая строка под названием |
| `quote` | слоган на странице товара |
| `lead` | описание |
| `notes` | пирамида аромата |
| `specs` | характеристики: `[{"k": "Состав", "v": "…"}]` |
| `images.card` / `images.hero` | фото в каталоге и на странице товара |
| `images.gallery` | дополнительные фото: `["assets/img/products/…webp"]` |

> ⚠️ Файл `data/products.json` влияет на сайт, только если Worker недоступен.
> Основные цены и остатки — в базе. После правок в кабинете обновляйте копию:
> «Выгрузка данных» → «Товары (JSON)» → положить файл в `data/`.

## 3. Фотографии и логотип

Все картинки — в **`assets/img/`**.

| Файл | Где используется |
|---|---|
| `logo.svg` | логотип в шапке |
| `hero.webp` | большое фото на главной (видно сквозь буквы RULES) |
| `favicon.svg` | иконка вкладки |
| `products/candle-*.webp` | фото свечей в каталоге |
| `products/candle-*-hero.webp` | большое фото на странице свечи |
| `products/diffuser-*.webp` | фото диффузоров |
| `products/set-*.webp` | фото наборов |
| `pages/craft.webp` | блок «Как рождается свеча» |
| `pages/mountains.webp` | фотография в блоке «Партнёрам» |
| `pages/promo-*.webp` | фото на промо-страницах |

**Как заменить фото:**

1. Откройте папку `assets/img/products` → нужный файл → значок карандаша.
2. Удалите файл и загрузите новый **с тем же именем** (так проще всего), либо
   загрузите новый файл и поправьте путь в каталоге/кабинете.
3. Форматы: `.webp` (лучше всего), `.jpg`, `.png`. Размер — до 1600 px по
   длинной стороне, вес до 300 КБ.

**Галерея на странице товара:** добавьте пути в `images.gallery`
(или загрузите фото в кабинете — поле «Большое фото»).

**Логотип:** замените `assets/img/logo.svg` (или укажите другой путь в
`data/settings.json` → `brand.logo`).

## 4. Цвета и шрифты

Откройте **`data/settings.json`**:

```json
"theme": {
  "ink": "#070707",       // основной тёмный фон
  "ink2": "#0d0d0d",      // фон карточек
  "bone": "#efeae0",      // основной светлый цвет текста
  "ash": "#8e887e",       // серый текст
  "emerald": "#0d5539",   // тёмно-зелёный
  "emerald2": "#2e8b62",  // акцент (цены, выделения)
  "ice": "#a9d8e8"        // голубой акцент
}
```

Меняете значение — меняется на всём сайте (цвета подставляются при загрузке).

Стили по умолчанию — в `assets/css/site.css`, первые строки `:root { … }`.
Если хотите поменять оформление «навсегда», правьте там.

**Шрифты.** В проекте три гарнитуры:

| Роль | Шрифт | Файлы |
|---|---|---|
| заголовки | Unbounded | `assets/fonts/unbounded-700.woff`, `unbounded-900.woff` |
| акценты, курсив | Instrument Serif | `instrument-serif-400.woff`, `-400-italic.woff` |
| текст | Manrope | `manrope-300/400/600/700.woff` |

Чтобы подключить другой шрифт: положите файлы в `assets/fonts/`, поправьте
`assets/css/fonts.css` (`@font-face`) и укажите название в
`data/settings.json` → `fonts.display` / `fonts.serif` / `fonts.text`.

## 5. Промокоды

`data/promos.json` (и такой же список внутри Worker — при изменении обновите оба):

```json
"RULES5": { "label": "5% на весь заказ", "percent": 5 },
"GORY10": { "label": "10% на ароматы «Горы»", "percent": 10, "family": "gory" },
"BOLSHOY15": { "label": "15% при сумме от 8 000 ₽", "percent": 15, "minSum": 8000 }
```

Подарочный промокод (подарок + бесплатная доставка) — те же два списка:

```json
"RYASOVLOVESYOU": {
  "label": "Набор «Дорога» в подарок и бесплатная доставка от 5 000 ₽",
  "percent": 0,
  "minSum": 5000,
  "gift": "set-doroga",
  "freeDelivery": true
}
```

`gift` — `id` товара из каталога, который приезжает бесплатно (строкой за 0 ₽ в заказе),
`freeDelivery: true` — доставка любым способом бесплатно.
Чтобы такой промокод работал, в Worker должна быть включена поддержка `gift` и `freeDelivery`
(см. [docs/07-obnovlenie.md](07-obnovlenie.md), раздел 9).

Проверка промокода при оформлении идёт на стороне Worker, поэтому
сайт и Worker должны знать одинаковый список.

## 6. Навигация, меню, футер

Шапка, мобильное меню, корзина и футер — в `index.html` (корень).
Ссылки меню — это `<a href="catalog.html">`; можно добавлять свои:
`<a href="about.html">О бренде</a>`.

---

## 7. Как проверить правку

1. Откройте сайт и страницу, которую правили (обновите с Ctrl/Cmd+Shift+R).
2. Если что-то не появилось — подождите 1–2 минуты (GitHub Pages собирает сайт).
3. Ошиблись — вернитесь в файл на GitHub, история правок хранится в «History»,
   любой коммит можно откатить.
