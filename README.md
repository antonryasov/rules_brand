# RULES · сайт магазина + личный кабинет (CRM)

Репозиторий для GitHub Pages со сайтом бренда RULES и отдельный Cloudflare Worker,
который принимает заказы, хранит их в базе D1 и обслуживает личный кабинет.

Главная идея: **всё, что видно на сайте, можно поменять без программиста** —
тексты лежат в папке `content/`, товары, цены и остатки — в `data/products.json`
и в личном кабинете, цвета и шрифты — в `data/settings.json`, фотографии — в
`assets/img/`.

## Быстрый старт

### 1. Сайт на GitHub

1. Загрузите содержимое этой папки в репозиторий `rules_brand` (замените старый `index-14.html`).
2. Settings → Pages → Source: **Deploy from a branch**, ветка `main`, папка `/ (root)`.
3. Через минуту сайт откроется по адресу `https://antonryasov.github.io/rules_brand/`.

> Старый монолитный `index-14.html` больше не нужен — его можно удалить из репозитория.

### 2. Worker и база

1. Откройте **`worker/worker.js`** и скопируйте **весь** файл.
   ⚠️ Именно `worker/worker.js` (собранный), а не `worker/src/worker.js` (исходник):
   в исходнике интерфейс кабинета ещё не вшит, и вместо входа вы увидите текст `__admin_html__`.
2. Cloudflare → Workers & Pages → ваш Worker → **Edit code** → вставьте код → Deploy.
3. Проверьте, что привязана база: Settings → Bindings → D1 database → **DB** → `rules-orders-db`.
4. В консоли D1 выполните `worker/schema.sql` (создаст таблицы CRM) и `worker/seed.sql` (зальёт товары).
5. Секреты (Settings → Variables and Secrets) — те же, что были, плюс проверьте `ADMIN_PASSWORD` и `SESSION_SECRET`.

Подробно: [docs/05-worker.md](docs/05-worker.md).

### 3. Личный кабинет

Откройте `https://ВАШ-WORKER.workers.dev/admin`, введите пароль из секрета `ADMIN_PASSWORD`.

Подробно: [docs/03-kabinet.md](docs/03-kabinet.md).

## Что можно делать в личном кабинете

| Раздел | Возможности |
|---|---|
| **Обзор** | заказы за сегодня, выручка, новые заказы, товары с низким остатком, состояние очереди Telegram |
| **Заказы** | список с поиском и фильтрами по статусу и датам; карточка заказа: смена статуса, трек-номер, оплата, способ получения и адрес доставки (город, индекс, улица и дом, квартира, подъезд), стоимость доставки, правка контактов покупателя, изменение состава заказа, внутренняя заметка |
| **Переписка по заказу** | комментарии продавца уходят покупателю в Telegram, ответы покупателя падают в карточку заказа, видно, что отправлено |
| **Вложения** | из карточки заказа можно отправить покупателю фото или документ (чек, накладную); вложения покупателя видны в переписке |
| **Товары и склад** | правка цены, остатка, порядка и видимости прямо в таблице; полный редактор товара (описания, ноты, характеристики, фото); загрузка фото с компьютера |
| **Импорт** | загрузка CSV/JSON со списком товаров, режим «заменить каталог» или «обновить существующие» |
| **Выгрузка** | заказы, товары, переписка, подписчики, полный бэкап — в CSV и JSON |
| **Рассылка** | новость подписчикам бота, история, очередь сообщений и повторная отправка |
| **Настройки** | тест бота заказов, подключение бота покупателей, шпаргалка «что где менять» |

**Доставка — адрес вводится в корзине.** Три способа получения: «Курьером по адресу»
(город, индекс, улица и дом, квартира, подъезд·этаж·домофон), «Самовывоз» и «Пункт выдачи
СДЭК» (только город — пункт подберём при подтверждении). Поля показываются по выбранному
способу, адрес проверяется до отправки и запоминается в браузере покупателя.
Никаких ключей и внешних сервисов для приёма заказов не нужно.

Стоимость доставки — по желанию, два места (значения должны совпадать):

* `data/settings.json` → `"delivery": { "courierCost": 390, "freeFrom": 5000, "pickupAddress": "…", "pickupNote": "…" }`
  (`0` = «стоимость согласуем», `freeFrom` = бесплатно от суммы товаров);
* переменные Worker `DELIVERY_COST`, `DELIVERY_FREE_FROM`, `PICKUP_ADDRESS`, `PICKUP_NOTE` —
  чтобы та же сумма попадала в заказ.

Подключение API СДЭК (необязательно, сейчас не используется) — [**docs/08-cdek.md**](docs/08-cdek.md).

**Бот покупателей** — меню с командами (`/orders`, `/status`, `/catalog`, `/help`),
список заказов кнопками, карточка заказа с составом и доставкой, выбор заказа для переписки,
приём фото и документов от покупателя.

**Как это связано с сайтом:** сайт при загрузке запрашивает у Worker адрес
`/catalog` — цены, остатки, фото и наличие берутся из базы D1. Поэтому изменение
цены или остатка в кабинете видно на сайте сразу после обновления страницы
(кеш 30 секунд). Если Worker недоступен, сайт работает на файле `data/products.json`.

## Локальный запуск (по желанию)

```bash
# сайт
cd rules-brand
python3 -m http.server 8080        # http://localhost:8080/index.html

# Worker + база
cd worker
npm install
npm run schema:local
npm run seed:local
npm run dev                        # http://localhost:8787/admin
```

Для локального запуска создайте `worker/.dev.vars` (он в `.gitignore`):

```
ADMIN_PASSWORD=тестовый-пароль-не-короче-16
SESSION_SECRET=любая-строка-длиной-не-короче-32-символов
TELEGRAM_BOT_TOKEN=...
TELEGRAM_CHAT_ID=...
CUSTOMER_BOT_TOKEN=...
CUSTOMER_BOT_USERNAME=rules_clients_bot
WEBHOOK_SECRET=...
ALLOWED_ORIGIN=http://127.0.0.1:8080
```

## Важно знать

- Адрес Worker для сайта задаётся в `data/settings.json` → `api.base`.
- Стоимость доставки и адрес самовывоза — `data/settings.json` → `delivery` (и те же значения
  в переменных Worker, если хотите, чтобы сумма попадала в заказ).
- Домен сайта для Worker — секрет/переменная `ALLOWED_ORIGIN` (CORS и подсказки в кабинете).
- Пароль в кабинет живёт только в секрете Cloudflare и никогда не попадает в репозиторий.
- Тексты страниц — обычный HTML: можно менять слова, добавлять абзацы, ссылки, картинки.
- Товары дублируются: в базе D1 (главный источник) и в `data/products.json` (резерв). После
  больших изменений в кабинете обновите резервную копию: «Выгрузка данных» → «Товары (JSON)».
